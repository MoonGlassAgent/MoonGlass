## 1. 定位（钉死，防漂移）

模块 UT 是**修复信心工具，不是证据替代品**：

- 全程走 probe 隔离通道（`run_simulation` purpose='probe' 同款隔离），**不写 scenario_hits、
  不进验证态势、不计入闭环证据**。闭环仍归 TOP 级回归（TOP-first 策略不变）。
- 反例纪律（case4 §7.3）：改 `gmac_axil_regs.v` 的 lint 修复搞坏了无关场景
  `SCN-0F47AE69`——跨模块副作用真实存在，UT 通过**不免除**全量重回归。

## 2. 入口与触发

- **用户自选**：会话指令（"对 gmac_rx_mac 做 UT"）或 UI 按钮（渲染端另队实现，见
  MODULE-UT-UI-HANDOFF-ZH-CN.md）。
- **软建议（非机械规则）**：同一 RTL 文件短期内被修复会话反复改动（≥2 次，由
  diagnostic-control 的 churn 统计推导）时，验证运行卡提示"该模块修复密集，建议发起
  模块 UT"。只提示，不自动派发。

## 3. 执行形态

- **一模组一独立会话**：单上下文完成"读模块+接口 → 搭最简 cocotb TB → 定向用例
  （含历史失败指纹）→ 跑 → 改 → 再跑"全程，无跨会话重复读入。
- **多模块并行**：不同模块的 UT 是多个并行子会话，互不干扰（各改各的文件）。
- **产出**：模块 UT 报告（过/不过 + 发现 + 改动清单），落盘
  `verification/results/ut/<module>/`（probe 隔离区口径）。
- **可选升级**：用户判定模块系统性弱 → 一键转 `register_ut_escalation`（治理版 UT，
  纳入证据链与门禁）。

## 4. rtlHash 与时序互斥（用户拍板的口径）

rtlHash 是**每次判定现算**的，不存在"刷新事件"。UT 期间防失效级联靠时序互斥而非冻结：

1. UT 会话持有 UT 锁（`verification/results/ut-sessions.json`，活跃计数制，
   多个模块 UT 可并行，全部结束才归零）；
2. UT 锁非空期间，主验证循环**互斥挂起**（不派回归拍）——没有并发判定，
   就没有"hash 中途变化污染判定"的问题；
3. UT 全部结束 → 锁归零 → 主循环恢复 → 现算 hash 与旧证据不同 → 受影响证据
   **一次性**标记待重验 → 重回归跑一次。

**禁止的方向**：冻结判定用 hash（冻结窗口内新证据的登记 hash 与实际 RTL 对不上，
证据说谎——证据诚实是底线）。

## 5. 强关恢复（锁释放）

- 锁在账本文件里，不在内存。启动对账（`reconcileRunLoopAfterRestart` 同款时机）发现
  state=active 的 UT 锁而会话进程已不存在 → **锁一律自动释放**，记录 `interrupted`
  （原因 app-restart）。
- 主循环重启后本来就不自动续跑（app-restart → paused-breaker 待人确认），提示中写明
  「UT 被强制中断，RTL 可能处于半截修改状态，请确认现场后再恢复」。
- 原则：**锁负责互斥，人负责现场**。两种失控组合（锁没放循环自动跑 / 锁放了循环对着
  半截 RTL 自动跑）都不存在。

## 6. UT 会话的工作要点（prompt 契约）

- 范围：指定模块 + 其直接依赖；TOP 级验证环境可复用（cocotb 基建/verilator shim/
  停滞保护），TB 建在 UT 隔离目录，不动主验证环境。
- 迭代自由：RTL 修改不限次数（probe 隔离，主链此时挂起）；改 RTL 前先确认问题定位。
- 结束条件：定向用例全过 + 报告落盘；或明确卡住 → 报告写明卡点，锁照常释放。
- 禁止：改主验证环境/scenario_hits/态势文件；扩大范围到其他模块（另发 UT）。

# MoonGlass ASIC Design Agent 实用手册

## 1. 首次配置

1. 在“设置”中添加并测试 LLM Provider，至少配置一个可用模型。
2. 检测本机开发环境与 EDA 工具链；按项目需要准备 Verible、Yosys、Verilator、Icarus Verilog、GTKWave、OpenSTA 等工具。
3. 新建项目时指定项目目录。MoonGlass 不会要求把工程集中存放到固定目录。

## 2. 六阶段流程

项目依次经过需求-规格定义、架构设计、RTL 开发、验证完备、质量检查和综合实现。双击阶段可进入该阶段；回到已完成的前序阶段并产生修改后，已完成的后续阶段会显示变更提醒，需要逐阶段响应或重新推进。

需求-规格定义阶段应持续维护需求-规格矩阵，保证需求、设计项、验证点和质量证据可追踪。

已有工程可直接选择原项目目录导入。MoonGlass 会根据文档、RTL、验证、QA 和综合证据建议实际阶段，用户确认后恢复阶段状态，并生成 `docs/01_project/import_assessment.md`。原目录结构和追踪方式不必与 MoonGlass 完全一致，后续可逐步建立映射。

“一键托管”可选择从当前阶段自动执行到指定阶段。托管会调用 Agent、自动处理推荐决策、执行门禁和修复重试；门禁仍失败时停止而非强制推进。每次托管完成、失败或停止都会生成完整报告。

## 3. Agent 会话

主会话用于持续推进当前阶段。平行会话可独立选择不同 Provider 和模型，用于交叉 Review、验证策略检查或问题定位。会话模型和历史记录会持久化；关闭应用后再次进入项目时加载原会话。

思考过程与工具调用采用流式展示。工具失败时先查看失败事件、参数和输出，再决定重试、切换模型或人工修复。中止按钮会请求终止当前 Agent 任务，但外部 EDA 子进程可能需要短暂清理时间。

## 4. 文件与设计浏览

项目文件树支持双击打开文本、RTL 和波形文件。`.fst`、`.vcd` 等波形依赖本机 GTKWave；RTL Design Browser 用于展开层次、查看模块实例和设计关系。大型层次首次解析可能耗时，后续可使用缓存结果或主动重新解析。

## 5. 质量与交付

每个阶段应保留规格、Review 记录、门禁结果、仿真报告、覆盖率、综合日志和签核清单。Agent 可生成和检查材料，但最终设计决策、工具结果解释、第三方许可与流片签核仍由工程负责人承担。

项目后期出现需求、规格或第三方缺陷时，使用“发起变更”建立变更单并选择最早影响阶段。已有后续结果会保留，完成过的受影响阶段显示黄色提醒，可人工逐项响应或再次使用一键托管完成 RTL 修复、验证回归、QA 审查和重新综合。

## 6. 数据与授权

项目、会话和模型配置默认保存在本机。调用外部模型时，发送的数据受服务商条款约束。MoonGlass 采用 PolyForm Noncommercial License 1.0.0；商业使用须提前取得书面授权，联系 `moonglassagent@126.com`。
